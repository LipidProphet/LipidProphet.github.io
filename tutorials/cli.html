Repeat a workspace from the command line.

Once a workspace runs in the desktop app, you can score the same inputs from a script and save the exact settings used.

  • Command line
  • Java 21

Locate the application and the workspace

Use Java 21 and keep LipidProphet.jar with its packaged dependencies. Run the example from the directory containing the JAR. Replace the quoted paths with the actual locations of your study and an existing output folder.

java -jar LipidProphet.jar --help

Score the LC–MS liver example

Use the workspace from the quick start. This command reads its acquisition settings and writes new filenames for both the table and the effective workspace.

java -jar LipidProphet.jar --cli --input-values "lcms-liver/results/input_values.txt" --output "lcms-liver/results/cli_results.tab" --save-input-values "lcms-liver/results/cli_workspace.txt"

--input-values and --save-input-values are required. The saved workspace must have a separate filename from the source. Choose fresh filenames for each run, or explicitly pass --overwrite to replace existing outputs.

The workspace supplies the TargetDB profile. For an explicit override, --target-db-workflow accepts lcms, msall, or ms-imaging. The imaging profile has the same input requirements as the graphical app.

Check what the script produced

A successful run prints All done!, the entry count, and the elapsed time. Exit code 0 indicates success. The example leaves its scored .tab file and effective .txt workspace together in the results folder.

Open the table and apply the same score and grouping rule you would use for a graphical run.
